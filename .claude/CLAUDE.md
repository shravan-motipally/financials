# Rules for changes in this repo

1. Split every task into 4 categories: UI/UX, API layer, data layer, infrastructure/DevOps. For each category the task touches, check `docs/best-practices/` for a guide covering the ask. If no guide exists, research and add one. If a guide exists but doesn't cover the ask, update it with the missing best practice.
2. Use the relevant best-practices guide(s) as the reference for how the ask gets built.
3. Don't agree by default. Read the ask and actually evaluate it: does it make sense, and what are we sacrificing by going this route — are we okay with that tradeoff? State this briefly, as a one-sentence ELI5.
